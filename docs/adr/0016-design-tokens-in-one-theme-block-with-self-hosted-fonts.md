# Design tokens live in one `@theme` block, and the two typefaces ship as ordinary dependencies

MiCare's palette, type scale, spacing rhythm, radii, shadows and focus treatment are declared once, in the Tailwind v4 `@theme` block at the top of `src/styles.css`, and reach the application only as utility classes. There is no JavaScript theme object, no second copy of the hex values in a constants module, and no component that hard-codes a colour. The design system this encodes is the "MiCare Foundations" set, whose source documents are committed under `docs/design/`.

**One block, because a token that exists twice is a token that will disagree with itself.** Before this slice every screen reached for stock Tailwind utilities — `bg-black`, `text-gray-700`, `text-red-600` — which meant the four Verification Statuses and the six Subscription Statuses had no colours of their own, and the ones they borrowed carried Tailwind's meanings rather than MiCare's. Naming them (`--color-verified`, `--color-sub-past-due`) does more than centralise a hex: it makes the domain's own vocabulary the thing a component asks for, so `bg-past-due` cannot drift from the rule that a past-due listing stays public. The state hues come in threes — hue, background, border — plus a separate `-ink` variant, because the hue that reads as a 5.8:1 chip border is not the hue that reads as accessible text on a white card, and offering both under distinct names is the only reliable way to stop the wrong one being used for body copy.

**Fonts are self-hosted, and self-hosted via the package manager.** Newsreader and Public Sans arrive as `@fontsource-variable/*` dependencies and are `@import`ed into the stylesheet; Vite resolves them from `node_modules` at build time and emits the woff2 files as ordinary hashed assets. The alternative approaches were both worse. A runtime call to a font host would tell a third party which consumer looked up which optician and when, on a site whose entire proposition is that it is a plain, trustworthy register — and it would put a render-blocking dependency on someone else's uptime. Committing the binaries, or adding a script that downloads them at build time, would put fonts outside the dependency graph the lockfile already guards and would need the Vercel build config changed to run it. Taking them as dependencies keeps the build untouched and makes the font versions as reviewable as any other upgrade. The tests assert the outcome directly: every `@font-face` the compiled stylesheet declares points at a relative URL, so a future `@import` from a CDN fails CI rather than shipping.

The families are named `Newsreader Variable` and `Public Sans Variable` in `--font-serif` and `--font-sans`, not the bare `Newsreader` and `Public Sans` the design documents use. That is Fontsource's family name for the variable cut, and naming anything else would leave the token pointing at a face that is not loaded and silently falling through to Georgia.

**Two families, not three.** The design specimens set hex values and token names in JetBrains Mono, but that is chrome belonging to the specimen, not to MiCare. The one place a monospace face would have reached real UI is the GOC-number error message, where the body face's tabular figures line the digits up just as well. So no mono package is installed and `--font-mono` is left at Tailwind's default stack, which saves a third font download on every first paint for a set of users who are disproportionately on slow connections and old devices.

**The root font-size is left alone.** Every `--text-*` token is calibrated against a 16px root, so raising `html { font-size }` would inflate the whole documented scale by the same factor — and, worse, would override the font size a partially-sighted consumer has deliberately set in their browser, on a directory whose users are substantially people with impaired vision. The responsive step from 17px to 18px therefore lives on `body`, where it changes the body copy without compounding through every rem in the system. A test asserts that no rule in the compiled stylesheet sets `font-size` on `html` or `:root`, because this is the kind of change that looks harmless in review.

**`color-scheme: light` is pinned rather than omitted.** Dark mode is deferred past v1: the palette's warmth comes from paper (`#FBF8F3`) rather than from white, and inverting it well is a design exercise, not a token swap. Without the declaration, a visitor whose OS is set to dark gets the browser auto-darkening selects, scrollbars and autofill against a light page — a half-inverted form, which is worse than either scheme. Stating the intent costs one line and can be revisited when a dark palette actually exists.

**The tokens are guarded by tests that compile the stylesheet, not by tests that read it.** `tests/unit/design-tokens.test.ts` runs `src/styles.css` through Tailwind's own compiler and asserts on what a browser would receive: that `bg-verified-bg` paints `#e8f3ea`, that `text-h1` renders at 34px on a default root, that `p-6` is 24px. Asserting on the compiled output rather than the source text means the tests survive the block being reordered or recommented, and they catch the failure mode that matters — a token renamed such that the utility silently stops resolving — which a regex over the source would not.

**The design sources are committed despite `docs/` being gitignored.** `docs/design/*.dc.html` were added with `git add -f`, the same way ADR-0015 landed. Later slices build components against these specimens, and a reference that lives only in an external tool is a reference that can disappear between one slice and the next.
