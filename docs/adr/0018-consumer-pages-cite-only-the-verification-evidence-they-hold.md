# The consumer pages cite only the Verification evidence they actually hold

`/search`, `/p/<short_id>/<slug>` and the two Notify-Me token pages now render from the design system: MiCare tokens, the Slice 31 primitives, and two new shared components — `PractitionerResultCard` and `NoticePage`. Behaviour is unchanged; no loader, server function or validation was touched.

**The badge on both consumer pages is the inline chip, not the plaque, because the plaque would have to invent its evidence.** The design puts the full Verification plaque on the profile page: profession in the headline, `General Optical Council · reg. 01-31842`, and a check date. `PublicProfile` carries none of those three, and `SearchResult` carries none either — the register check is what made the Practitioner visible in the first place, but the GOC number, the Profession and `last_verified_at` never reach the browser. Rendering the plaque would therefore mean either widening the public payload (a loader change this slice was explicitly scoped out of) or printing a citation MiCare does not have in hand. So `VerificationBadge` was widened instead: `registrationNumber` and `profession` are now optional, and the badge composes its `aria-label` from what it was given, exactly as ADR-0017 already required for the check date. A badge with no number says "General Optical Council"; it never says "reg. undefined", and it never says a number.

The consequence is deliberate and visible: the profile's trust moment is currently a chip plus a sentence rather than the designed plaque. Restoring the plaque is a payload decision — put the GOC number, the Profession and the last check date on `PublicProfile` — and it belongs to whoever decides that a registration number is public data on a MiCare page. The register itself is public; that is not the same as MiCare choosing to republish it.

**Two shared components came out of the four screens, and no more.** `PractitionerResultCard` is the design's result card and renders the `<li>` itself, because the hairline that separates rows has to belong to the row: a `last:border-b-0` on the link inside it matches every time — the link is the only child of its row — so every result would lose its rule instead of only the final one. `NoticePage` is the frame for the six screens that are the end of a journey rather than a step in one (confirmed, unsubscribed, either token page handed a link it cannot read, and the two profile dead ends); each states the outcome in a word with its own glyph, then in a sentence, then offers one way onward. The Notify-Me capture stayed inside `search.tsx`, because it holds the server-function call and the E2E suite already exercises it end to end.

**Button chrome and link chrome are shared as classes, not as components.** One thing on the site is a primary button and cannot be a `<button>`: the profile's "Book an appointment" leaves for the Practitioner's own site through `/go`, so it must be an anchor the browser fully navigates for the Click-through to be counted. `buttonClasses()` is what `Button` itself is built from, so the anchor wears the button rather than a hand-typed copy of it — the copy is what a test caught first time round, as a stray `text-white`. `TEXT_LINK_CLASSES` exists for the same reason on the other side: a route navigating inside MiCare uses TanStack's `Link`, which takes a `className` but is not an `<a>` we can wrap.

**The route guards assert the source, because the subject is the source.** ADR-0016 argued that a regex over `src/styles.css` proves less than compiling it, and that still holds for tokens. But a TanStack file route cannot be mounted without a router, and the two properties this slice has to keep are properties of the files: that no screen reaches past the tokens for `bg-black` or `text-gray-700`, and that every `data-testid` the E2E suite navigates by — plus the `data-hydrated` marker Slice 6 added to stop a click racing the native form submit — is still there. `tests/unit/consumer-routes.test.ts` reads the four route files and asserts exactly that, per route and per marker, so a marker deleted in a later restyle fails a unit test in seconds rather than an E2E run in minutes.
