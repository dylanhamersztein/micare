# Signup claims only what it can prove

`/signup`, `/login`, `/auth/callback` and the two Checkout return pages now render from the design system: MiCare tokens, the Slice 31 primitives, and two new shared components — `VerificationWait` and `SignupOutcome`. No server function, validation rule or Checkout hand-off changed.

**The wait is a record of what is being done, not a spinner over a greyed page.** Four or five seconds is long enough for a Practitioner to wonder whether the form submitted at all, and this is the one screen where they watch MiCare do the thing MiCare sells. So `VerificationWait` names the register and the number and lists the three stages of the request. What it deliberately does not have is a percentage or a progress bar: the GOC register never tells us how far along it is, and a bar that stalls at 80% reads as broken. The three stages are the stages of the request, not a live readout — nothing polls the server, so nothing pretends to — and only the running line carries `aria-live="polite"`, because a live region per row announces the whole list three times over. The one moving thing is `aria-hidden`, and the stylesheet's global `prefers-reduced-motion` rule stops it; the state is already carried by the word "Checking…", so nothing is lost.

**Pending promises no robot, and no email.** The weekly sweep re-verifies visible Practitioners, so a `pending` result at signup is cleared by an operator running Manual Re-verification (ADR-0014) and by nothing else. The old copy said "someone will follow up shortly", which claimed a contact MiCare cannot make: a pending signup writes one row to `verifications` carrying the submitted name and the GOC number, and no Practitioner row and no email address exist yet. The copy therefore says what is true — nothing retries in the background, a person re-runs the check by hand, normally within one working day — and offers the Practitioner the button that is often faster than either: run it again themselves. `tests/unit/components/signup-outcome.test.tsx` holds both halves of that, asserting the operator sentence is present and that no sentence promises to email anyone.

**Not-found is a statement about our search, never about the person.** The rejected outcome shows back exactly what was searched for, then three recoverable reasons ordered by likelihood, and states in the same breath that there is no charge — a Practitioner's first question after a failed check is whether they have paid for nothing, so every one of the three outcomes says where they stand on money. The first reason quotes the register's format, and that format is now `GOC_NUMBER_HELP` in `src/goc-number.ts`, declared beside the pattern it describes. Field help, error copy and rejection reason are one string with one home, and `tests/unit/goc-number.test.ts` parses every example the copy prints and fails if either prefix shape stops being shown. Copy that shows an example is making a claim about what the schema accepts; it is checked like one.

**Signup renders the Verification plaque that ADR-0018 could not.** The consumer pages fall back to the inline chip because `PublicProfile` carries neither the GOC number nor the Profession. Signup holds both: the prospect typed the number a moment ago, and Phase 1 has exactly one Profession. What signup does not hold is a check timestamp — `submitSignup` returns an outcome and nothing else — so the badge takes its own dateless fallback and cites the cadence instead of a date it was never given.

**The Phase-1 Profession is a stated fact, not a select with one option.** One option is not a choice: a single-item dropdown reads as a decision the Practitioner has to make and then cannot. The screen states "Optician", names the register that implies, and carries the value in a hidden input — which is where the `signup-profession` marker moved to. The select returns on the day a second regulator ships.

**"Try again" resets the panel; it does not navigate.** Both failed outcomes previously offered a `Link` to `/signup` from `/signup`, which changes no route state and therefore leaves the panel exactly where it is. They now clear the outcome back to the form, with everything the Practitioner typed still in it — the fastest fix for a mistyped digit is the field with the digit in it. Nothing about the submit path changed: the pending retry calls the same `runCheck` the form calls.

**The route guards grew a second slice.** `tests/unit/consumer-routes.test.ts` and the new `tests/unit/acquisition-routes.test.ts` now share `tests/unit/support/route-source.ts`, so there is one definition of what a guarded route is: no stock-Tailwind palette utility anywhere in the file, every `data-testid` the E2E suite navigates by still present, and the `data-hydrated` marker still on any route that carries a form. `/auth/callback` is in the list with no markers at all — it is a server-route handler with no component — so that the day it grows a rendered error state, that state is born on the design system rather than retrofitted onto it.
